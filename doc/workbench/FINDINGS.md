# Workbench findings

Bugs and oddities the Recoil Workbench has surfaced, newest first. Each entry says how it was found and what happened to it.

| Date | Area | Finding | How found | Status |
|---|---|---|---|---|
| 2026-09-24 | Engine (upstream, gameplay) | **Suspected: units behind a weapon's firing point can block its line of fire.** A conservative bounding-sphere pre-check in `TraceRay` (reject objects the ray segment misses by more than their bounding radius + 1 elmo) changed the game; with the ray extended *backwards* without limit it matched exactly (0 misses, identical checksums over 3,000 frames). So `DetectHit`/`IntersectCylinder` reports hits behind the ray start, and `TraceRay` accepts them at distance 0 (`GetHitPosDist` clamps to 0). Handling those cases is ~1/3 of big-battle sim time (the segment-only pre-check ran big_battle at 4.8-5.5 ms/frame vs 7.4-8.0). | Profiling + sphere pre-check experiments on lemon | **Open**: prove with a targeted scenario (a unit directly behind a shooter), then decide: fixing it changes gameplay |
| 2026-09-24 | Engine (our perf patch) | Batched unit deletion freed each unit before the batch's compaction pass, so while `RenderUnitDestroyed` ran for a later unit, `activeUnits` still listed already-freed units: a widget calling `Spring.GetAllUnits()` there read freed memory. The compaction also compared freed pointer values (ABA-prone), and its scratch buffers were function statics (non-reentrant). | Independent code review of the fork's sim patches | Fixed: memory is freed after compaction; scratch buffers are members guarded against re-entry; compaction is `spring::VectorEraseSorted`, unit-tested against the old erase (`test_ContainerUtil`) |
| 2026-09-24 | Engine (our perf patch) | `Spring.GetVisibleUnits`' per-frame cache ignored `Spring.SetUnitNoDraw` calls in the same frame, returning the hidden unit. | Code review | Fixed: `SetUnitNoDraw` invalidates the cache; guarded by the `lua_api_regressions` scenario |
| 2026-09-24 | Engine (our perf patch) | LOS, radar and air-LOS info textures compared per-ally-team change counters without remembering the ally team, so after switching the viewed team they could keep showing the previous team's coverage. | Code review | Fixed: the textures also track the ally team they last drew |
